# OPS-003 · SEO: static HTML for public pages, Spanish URLs, rules and hand rankings

- **Level:** M · **Status:** implemented (pending deploy + text review) · **Owner:** Guillermo · **Created:** 2026-10-17
- **Repos:** client (build, router, pages, locales, nginx), root (Caddyfile) · **Flags:** —
- **Supersedes:** OPS-002 R-02 (head handling). OPS-002 R-01 still holds: no Puppeteer/Chromium.

## 1. Audit (production, 2026-10-17)

- Every URL returns the same 4 KB file whose body is only `<div id="app"></div>`
  (`client/index.html`); the text is painted by JS. Crawlers that don't run JS see nothing, Google
  renders late, link previews show no content.
- `/`, `/about`, `/privacy`, `/terms`, `/contact` are byte-identical: same title, description and
  `canonical: https://yaypoker.com/` → Google treats them as duplicates of an empty home page.
  Only `document.title` changes, client-side (`client/src/router.js:99`).
- nginx falls back to `index.html` for every path (`client/Dockerfile`, `try_files … /index.html`):
  unknown URLs answer 200 (soft 404).
- `www.yaypoker.com` serves the site too (`Caddyfile:2`) instead of redirecting to the apex.
- `og:image` points to `/og-image.jpg`, which doesn't exist (returns the HTML shell).
- Language is chosen in JS from `localStorage`/browser (`client/src/i18n.js`); Spanish has no URL, so
  it can't be indexed. `index.html` reads key `locale`, `i18n.js` writes `user-locale` (mismatch).
- Theme class (`dark`) is set by JS (`client/src/store/themeStore.js`), so static HTML would flash the
  light theme.
- No content that people search for (rules, hand rankings).

**Options considered**
1. Puppeteer prerender — rejected in OPS-002 (VPS memory).
2. **Build-time Vue SSR (`vite build --ssr` + `renderToString`) of the public routes, no browser** —
   chosen: same components and texts as the SPA, low memory, runs inside the existing Docker build.
3. Hand-written static HTML per page — duplicates every text, drifts from the SPA.

**Decisions (human, 2026-10-17):** fix SEO; include Spanish URLs under `/es`; include rules and hand
rankings pages in this spec.

## 2. Requirements

Public pages (the "SEO set"), each in English and Spanish:

| English | Spanish | Page |
|---|---|---|
| `/` | `/es` | Home |
| `/about` | `/es/about` | About |
| `/rules` | `/es/rules` | Texas Hold'em rules (new) |
| `/hand-rankings` | `/es/hand-rankings` | Poker hand rankings (new) |
| `/privacy` | `/es/privacy` | Privacy |
| `/terms` | `/es/terms` | Terms |
| `/contact` | `/es/contact` | Contact |

- R-01 For every SEO-set URL the server SHALL return HTML whose `<body>` already contains the page's
  rendered content (at least one `<h1>` and its body text), produced at build time without a browser.
- R-02 Each SEO-set page SHALL have its own `<title>`, meta description, `<html lang>`, self-referencing
  absolute canonical, `og:*`/`twitter:*` tags, and `hreflang` alternates (`en`, `es`, `x-default` → English).
- R-03 The language of an SEO-set page SHALL be decided by its URL. The EN/ES switcher on these pages
  SHALL navigate to the counterpart URL; the choice is saved and used by the app pages (lobby, game).
- R-04 WHEN a visitor opens an English SEO-set page in the browser AND their saved locale (or, with none
  saved, their browser language) is Spanish, THE CLIENT SHALL replace the URL with the Spanish
  counterpart. This SHALL happen only in client JS (crawlers get the URL they asked for).
- R-05 Internal links between SEO-set pages SHALL stay in the current language. Home and the footer of
  public pages SHALL link to `/rules` and `/hand-rankings`.
- R-06 App routes (`/lobby`, `/public`, `/new`, `/join/*`, `/play/*`, `/watch/*`, `/verify/*`) SHALL keep
  working as today and SHALL be served with `noindex` and no canonical.
- R-07 Any other unknown path SHALL answer HTTP 404 with the existing NotFound page, `noindex`.
  Paths with a trailing slash SHALL 301 to the version without it.
- R-08 `www.yaypoker.com` SHALL 301 to `https://yaypoker.com` keeping path and query (port 8888 unchanged).
- R-09 `/og-image.jpg` SHALL exist (1200×630 JPEG, brand image).
- R-10 `sitemap.xml` SHALL list all 14 SEO-set URLs with `xhtml:link` hreflang alternates and be
  generated by the build from the same page list; `robots.txt` keeps pointing to it.
- R-11 The rules page SHALL explain, accurately and consistent with the game engine: seats, button and
  blinds; hole cards; the four betting rounds; check/bet/call/raise/fold/all-in; showdown and split pots;
  side pots; how a game on YayPoker works (private/public tables, virtual chips only).
- R-12 The hand rankings page SHALL list the 10 hands from royal flush to high card, each with a short
  explanation and an example drawn with the existing card component, plus tie-break (kicker) notes.
- R-13 The theme class SHALL be applied before first paint (inline script), so static HTML shows the
  saved theme (dark by default) with no flash.
- R-14 After JS loads, the visible page SHALL be the same content as the static HTML (no text change
  for a visitor who stays on the URL's language).
- R-15 The build SHALL fail if any SEO-set page renders without an `<h1>`, with a duplicate title or
  description, or with a wrong canonical.

**Inherited invariants:** no real money wording changes (virtual chips only); no secrets or logs served
(the 404 change makes `/Logs/*` answer 404 instead of the SPA shell); OPS-002 R-01 (no Chromium).

## 3. Design

- `client/src/seo/pages.js` — single list of SEO-set pages: path per locale, title/description i18n keys.
  Used by the router, the head updater, the prerender script and the sitemap.
- `client/src/router.js` — exports `routes` and `createAppRouter(history)`; adds `/rules`,
  `/hand-rankings` and the `/es/*` routes (`meta.locale`). `beforeEach` sets the i18n locale from
  `meta.locale` on SEO-set routes and updates title, description, canonical and `lang`.
- `client/src/entry-server.js` — `render(url)` → `createSSRApp`, fresh Pinia, memory-history router,
  locale from the route, `renderToString`.
- `client/scripts/prerender.mjs` — runs after `vite build` + `vite build --ssr`; installs jsdom globals
  (stores read `window`/`localStorage` at setup), renders each SEO-set URL into
  `dist/<path>/index.html`, writes `dist/app.html` (shell, `noindex`), `dist/404.html` (NotFound,
  `noindex`), `dist/sitemap.xml`; runs the R-15 checks. `npm run build` chains all three steps.
- `client/src/main.js` keeps `createApp(...).mount('#app')` (replaces the static markup; no hydration
  mismatch risk from screen-size-dependent layouts).
- `client/nginx.conf` replaces the inline `printf` in the Dockerfile:
  assets → file or 404; app routes → `/app.html` + `X-Robots-Tag: noindex`; everything else →
  `$uri` / `$uri/index.html` or 404 with `/404.html`; trailing-slash 301.
- `Caddyfile` — `www.yaypoker.com { redir https://yaypoker.com{uri} permanent }`.
- `client/public/og-image.jpg` — generated once from an SVG (logo + tagline) and committed.
- Content for rules and hand rankings lives in `en.json`/`es.json` (`pages.rules`, `pages.hand_rankings`).
- Remove the `keywords` meta (ignored by search engines). JSON-LD `VideoGame` stays on home only.

## 5. Edge cases

- Saved locale `en` + browser `es` on `/` → stays on `/` (saved choice wins).
- Old links to `/index.html` keep working (served as home; canonical points to `/`).
- Spectator/game URLs shared before the change keep working (R-06).
- Spanish visitor clicks EN on `/es/rules` → `/rules`, saves `en`, no redirect loop (R-04 reads the
  saved value, which is now `en`).

## 6. Out of scope

Google Search Console setup (owner action, needs the account), backlinks, blog content, structured data
beyond the existing `VideoGame`.
